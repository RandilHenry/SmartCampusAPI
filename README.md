# SmartCampusAPI

A RESTful API for managing rooms and sensors across a university smart campus, built with JAX-RS (Jersey 2.41) and deployed on Apache Tomcat 9.

## API Design Overview

The API follows RESTful principles with a clear resource-based hierarchy
that reflects the physical structure of the campus:
/api/v1/                              → Discovery endpoint (HATEOAS)
/api/v1/rooms                         → Room collection
/api/v1/rooms/{roomId}                → Single room operations
/api/v1/sensors                       → Sensor collection
/api/v1/sensors/{sensorId}            → Single sensor operations
/api/v1/sensors/{sensorId}/readings   → Sensor reading history (sub-resource)

### Core Data Models

**Room**
Represents a physical room on campus.
- `id` — Unique identifier (e.g. `LIB-301`) 
- `name` — Human-readable name (e.g. `Library Quiet Study`)
- `capacity` — Maximum occupancy for safety regulations
- `sensorIds` — List of sensor IDs deployed in this room

**Sensor**
Represents a hardware sensor deployed in a room.
- `id` — Unique identifier (e.g. `TEMP-001`)
- `type` — Category (e.g. `Temperature`, `CO2`, `Occupancy`)
- `status` — Current state: `ACTIVE`, `MAINTENANCE`, or `OFFLINE`
- `currentValue` — Most recent measurement recorded
- `roomId` — Foreign key linking sensor to its room

**SensorReading**
A timestamped historical data point recorded by a sensor.
- `id` — UUID generated by the server
- `timestamp` — Epoch time (ms) when the reading was captured
- `value` — The actual metric value recorded

### Key Design Decisions

**In-memory storage**
Data is stored using ConcurrentHashMap — thread-safe and requires
no database. All data resets when the server restarts.

**Per-request lifecycle**
JAX-RS instantiates a new resource class for every incoming request. Shared state is therefore managed through a singleton DataStore class rather than instance fields in resource classes.

**Sub-resource locator pattern**
Sensor readings are managed by a dedicated SensorReadingResource class, delegated to via a sub-resource locator in SensorResource. This keeps concerns separated and the codebase maintainable.

**Business logic constraints**
- A room cannot be deleted if it has ACTIVE sensors assigned to it
- Only ACTIVE sensors can record new readings
- Sensors with status MAINTENANCE or OFFLINE are blocked from accepting readings with a 403 Forbidden response

**Custom exception mapping**
All errors are intercepted by dedicated exception mappers. Raw Java stack traces are never exposed to API consumers. All errors return structured JSON responses with meaningful messages.

**Logging filter**
A single JAX-RS filter implements both ContainerRequestFilter and ContainerResponseFilter to log every request and response automatically across all endpoints.

## How to Build and Run

### Prerequisites

- Java JDK 11 or higher installed
- Apache Tomcat 9 installed
- Apache NetBeans IDE (recommended) or any Maven-compatible IDE
- Maven 3.x

### Run via NetBeans 

**1. Clone the repository**
```bash
git clone https://github.com/RandilHenry/SmartCampusAPI.git
```

**2. Open the project**
- Open Apache NetBeans
- File → Open Project
- Navigate to the cloned `SmartCampusAPI` folder and open it

**3. Configure Tomcat (first time only)**
- Go to Services tab → Servers → Add Server
- Select Apache Tomcat 9
- Point it to your Tomcat installation directory
- Set a username and password 

**4. Build the project**
- Right-click the project → Clean and Build
- Wait for `BUILD SUCCESS` in the output window

**5. Run the project**
- Right-click the project → Run
- NetBeans deploys the WAR to Tomcat automatically
- Tomcat starts and the API becomes available

**6. Verify**
```bash
curl http://localhost:8080/SmartCampusAPI/api/v1/
```

## API Endpoints

### Discovery

| Method | Path        | Description              | Response |
|--------|-------------|--------------------------|----------|
| GET    | `/api/v1/`  | API metadata and links   | 200 OK   |

### Rooms — `/api/v1/rooms`

| Method | Path                    | Description                        | Response        |
|--------|-------------------------|------------------------------------|-----------------|
| GET    | `/rooms`                | List all rooms                     | 200 OK          |
| POST   | `/rooms`                | Create a new room                  | 201 Created     |
| GET    | `/rooms/{roomId}`       | Get a specific room by ID          | 200 OK / 404    |
| DELETE | `/rooms/{roomId}`       | Delete a room (no active sensors)  | 204 / 404 / 409 |

### Sensors — `/api/v1/sensors`

| Method | Path                    | Description                          | Response        |
|--------|-------------------------|--------------------------------------|-----------------|
| GET    | `/sensors`              | List all sensors                     | 200 OK          |
| GET    | `/sensors?type=CO2`     | List sensors filtered by type        | 200 OK          |
| POST   | `/sensors`              | Register a new sensor                | 201 Created     |
| GET    | `/sensors/{sensorId}`   | Get a specific sensor by ID          | 200 OK / 404    |

### Sensor Readings — `/api/v1/sensors/{sensorId}/readings`

| Method | Path                              | Description                    | Response        |
|--------|-----------------------------------|--------------------------------|-----------------|
| GET    | `/sensors/{sensorId}/readings`    | Get all readings for a sensor  | 200 OK / 404    |
| POST   | `/sensors/{sensorId}/readings`    | Add a new reading              | 201 Created / 403 / 404 |

## Sample curl Commands

### 1. Discovery endpoint
```bash
curl -X GET http://localhost:8080/SmartCampusAPI/api/v1/ \
  -H "Accept: application/json"
```
Expected response:
```json
{
  "api": "Smart Campus Sensor & Room Management API",
  "version": "1.0",
  "contact": "admin@smartcampus.ac.uk",
  "resources": {
    "rooms": "http://localhost:8080/SmartCampusAPI/api/v1/rooms",
    "sensors": "http://localhost:8080/SmartCampusAPI/api/v1/sensors"
  }
}
```

### 2. Get all rooms
```bash
curl -X GET http://localhost:8080/SmartCampusAPI/api/v1/rooms \
  -H "Accept: application/json"
```

### 3. Create a new room
```bash
curl -X POST http://localhost:8080/SmartCampusAPI/api/v1/rooms \
  -H "Content-Type: application/json" \
  -d "{\"id\":\"CS-101\",\"name\":\"Computer Science Lab\",\"capacity\":35}"
```
Expected response:
```json
{
  "id": "CS-101",
  "name": "Computer Science Lab",
  "capacity": 35,
  "sensorIds": []
}
```

### 4. Get a specific room
```bash
curl -X GET http://localhost:8080/SmartCampusAPI/api/v1/rooms/LIB-301 \
  -H "Accept: application/json"
```

### 5. Delete a room that has active sensors (expect 409 Conflict)
```bash
curl -X DELETE http://localhost:8080/SmartCampusAPI/api/v1/rooms/LIB-301 \
  -H "Accept: application/json"
```
Expected response:
```json
{
  "error": "Room cannot be deleted",
  "reason": "Room 'LIB-301' is currently occupied by 1 active hardware sensor(s). Decommission all sensors before removing the room.",
  "status": 409
}
```

### 6. Get all sensors
```bash
curl -X GET http://localhost:8080/SmartCampusAPI/api/v1/sensors \
  -H "Accept: application/json"
```

### 7. Get sensors filtered by type
```bash
curl -X GET "http://localhost:8080/SmartCampusAPI/api/v1/sensors?type=CO2" \
  -H "Accept: application/json"
```

### 8. Register a new sensor
```bash
curl -X POST http://localhost:8080/SmartCampusAPI/api/v1/sensors \
  -H "Content-Type: application/json" \
  -d "{\"id\":\"HUM-001\",\"type\":\"Humidity\",\"status\":\"ACTIVE\",\"currentValue\":55.0,\"roomId\":\"LIB-301\"}"
```

### 9. Register a sensor with an invalid roomId (expect 422)
```bash
curl -X POST http://localhost:8080/SmartCampusAPI/api/v1/sensors \
  -H "Content-Type: application/json" \
  -d "{\"id\":\"HUM-002\",\"type\":\"Humidity\",\"status\":\"ACTIVE\",\"currentValue\":55.0,\"roomId\":\"INVALID-ROOM\"}"
```
Expected response:
```json
{
  "error": "Unprocessable Entity",
  "reason": "The roomId 'INVALID-ROOM' does not exist. Register the room before assigning sensors to it.",
  "status": 422
}
```

### 10. Post a reading to an active sensor
```bash
curl -X POST http://localhost:8080/SmartCampusAPI/api/v1/sensors/TEMP-001/readings \
  -H "Content-Type: application/json" \
  -d "{\"value\":23.7}"
```
Expected response:
```json
{
  "id": "a3f1c2d4-...",
  "timestamp": 1713456789000,
  "value": 23.7
}
```

### 11. Post a reading to a MAINTENANCE sensor (expect 403)
```bash
curl -X POST http://localhost:8080/SmartCampusAPI/api/v1/sensors/OCC-001/readings \
  -H "Content-Type: application/json" \
  -d "{\"value\":10.0}"
```
Expected response:
```json
{
  "error": "Sensor unavailable",
  "reason": "Sensor 'OCC-001' is under MAINTENANCE and cannot record readings.",
  "status": 403
}
```

### 12. Get all readings for a sensor
```bash
curl -X GET http://localhost:8080/SmartCampusAPI/api/v1/sensors/TEMP-001/readings \
  -H "Accept: application/json"
```

## Error Handling

The API uses custom exception mappers to ensure all errors return
structured JSON. Raw Java stack traces are never exposed.

| HTTP Status | Scenario                                          |
|-------------|---------------------------------------------------|
| 400         | Missing required fields (e.g. no ID provided)     |
| 403         | POST reading to a MAINTENANCE or OFFLINE sensor   |
| 404         | Requested room or sensor does not exist           |
| 409         | Delete room that has ACTIVE sensors assigned      |
| 422         | Register sensor with a roomId that does not exist |
| 500         | Unexpected server error — logged server-side only |
